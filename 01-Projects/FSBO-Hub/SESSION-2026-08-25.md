## 1. Network-wide OG-image fix — 55plus-hub, boat-hub, closing-hub, condo-hub, investor-hub (all pushed)

Search Console was logging 404s on `opengraph-image` routes across these 5 repos, and any social share of their pages showed a broken preview. Root cause took two passes to fully fix:

- **Pass 1 (2026-08-21)** — `opengraph-image.tsx` declared `runtime = "edge"`, which `output: 'export'` cannot statically generate. Removing the directive was the first attempt (`c654837` boat-hub and equivalent in the other 4).
- **Pass 2 (2026-08-23)** — that wasn't enough: static export can't generate `ImageResponse` images at all, dynamic-runtime or not. Second commit (`dffeefa` boat-hub and equivalent) deletes the `opengraph-image.tsx` routes entirely, so Next stops auto-injecting URLs that 404 — pages now fall back to the `og-default.png` already sitting in `public/` and already wired into each layout. Per-state bespoke social images were the nicer option; a working generic image beats a broken one.
- Confirmed this also explains a `"TypeError: Invalid URL"` prerender failure that had been written off as Windows-only — it was the real bug surfacing locally on `@vercel/og`.
- **Swept the rest of the network for the same pattern** — only one other hit, `flatfee-hub/src/app/opengraph-image.tsx.bak`, a dead `.bak` file, not live. Rollout is complete; no repo still has a broken dynamic OG route.

## 2. fsbo-freemium-sandbox (production) — 3 more commits, all pushed

Production's `master` moved from `91ce945` (the 08-21 snapshot) to `f955716`:

- `1cd6b5c` (08-21) **seo: match the network's AI-crawler policy, drop a broken SearchAction** — this Netlify-hosted site was the only one in the network NOT blocking AI-training crawlers, because the other ~39 sites get that for free from Cloudflare's managed robots.txt and this one doesn't have an equivalent. Now blocks the same nine bots (Googlebot, OAI-SearchBot, PerplexityBot, Applebot deliberately left open). Also dropped a homepage `SearchAction` pointing at a search route that never existed — Google was crawling the literal `{search_term_string}` template and logging it as a 404 in Search Console.
- `33c0ef2` (08-21) **fix: state-blog 404s, and split the Boston offer-terms FAQ** — posts for the 22 states with no metro hub live at `/{state}/blog/{slug}` (fine) but the parent `/{state}/blog` index was never generated, so Google crawling up from an indexed post hit a 404 (8 showed in Search Console; all 22 buckets had the hole). Fixed with a redirect to the state guide rather than generating a real index (which would just be a noindexed page nobody can find, per the existing blog-index policy). Also split one dense Boston FAQ (Use & Occupancy / cash offers / PMI in one paragraph) into three separate Q&As, each getting its own `FAQPage` schema entry.
- `f955716` (08-25, **today**) **fix(build): never skip a manual redeploy** — the build-skip guard added 08-21 (`91ce945`, compares `CACHED_COMMIT_REF` to `COMMIT_REF`) is correct for pushes but wrong for a manual "Trigger deploy," where the two refs are identical — so `git diff` finds nothing and the build gets skipped. Notable: the commit message says this **was silently blocking the switch to live Stripe keys**, since Netlify only bakes env-var changes into a fresh build, and a manual redeploy with no code change is exactly how you'd apply a new secret. Worth confirming with Kevin whether live Stripe keys have now actually been applied, since the blocker that was preventing it is gone.
