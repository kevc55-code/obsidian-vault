**08-19 — page redesign + a real production incident, fixed same day:**
- `c120cd1` **fix(robots): stop disallowing crawlers on production** — a fail-closed robots guard (written under the mistaken belief this repo was a test site — see [[fsbo-repo-map]]) had shipped `Disallow: /` to fsbo.byownerhub.com, the site's #1 problem being indexation. Inverted to fail-open. This was already logged in [[fsbo-repo-map]] as an incident; confirming here it's the same fix, live.
- `7a0a24b` **feat(metro): make the page read as a tool, not an article** / `77b07d7` **fix(hero): get the tool above the fold** — start of the redesign.
- `da472e9` seo: stop this sandbox from competing with production; `ff50f92` paywall: gate the documents, never the seller's own work; `b6dbdbe` sync from fsbo-hub main.

**08-20 — the redesign finishes rolling out + two new entitlement features:**
- `6b1797a` **fix(suburb): add the step flow, and stop dropping state-specific items** — the redesign had only ever been wired into the metro page; all 780 suburb pages (majority of the site) still rendered the old layout. Also fixed a real bug: `getRelevantChecklistItems` matched on `metro.slug`, which suburb pages override with their own slug — so every metro/state-specific checklist item (e.g. Massachusetts-specific steps on Milton) was silently dropped on suburb pages.
- `d921580` **feat(metro): reveal one step at a time** — replaces "13 full-width sections dumped at once" with 4 collapsible steps (price it / list it / show & disclose / close), driven by the same state as the stepper and the checklist tabs. Collapsed steps stay in the DOM (hidden via CSS, not unmounted) specifically to preserve SSR'd content for crawlers — ~20,300 words still in the DOM vs ~2,500 visible.
- `38644d6` **fix(flow): highlight the step you clicked, and key services to their step** — stepper highlight was tracking progress, not selection, so clicking a step moved content but not the highlight. Also re-keyed the affiliate ServicesGrid from its own 3-phase model to the page's 4 real steps (photography had no category at all before this — those affiliates were never surfacing).
- `ebe6064` **fix(mobile): stop the page overflowing, and bring suburbs in line** — comps-estimator grid used `1fr` (= `minmax(auto,1fr)`) columns that couldn't shrink below ~20ch, forcing every metro/suburb page to 587px inside a 375px viewport. Fixed with `minmax(0,1fr)` + `min-w-0`. Suburb pages also got the full step-flow treatment applied here (was still missing the hero-CTA/spacing pass).
- `c434e83` **feat: refund revocation, and passwordless cross-device resume** — two features. (1) Stripe webhook had no `charge.refunded` handler at all — a refunded customer kept toolkit access despite the 30-day guarantee; now `revokePurchase()` flips purchase status so the download gate 403s. (2) New passwordless "resume" flow: seller requests an email link, opening it anywhere restores their workspace (checklist state, zip, comps, price estimate) via a new `workspaces` table (service-role only, RLS on). Explicitly **not a login** — a leaked resume link exposes square footage, not purchased content; paid access still keys off the verified Stripe session. Needs `RESEND_API_KEY` to actually send mail — without it, saves succeed but report `emailed:false`.
- `9546b3c` **fix(refunds): stop the guarantee giving the product away** — closes a loophole the revocation feature above exposed: revoking access after a refund doesn't retrieve the PDF, so an unconditional 30-day guarantee let anyone buy → download → refund → keep. Policy now: refundable for 30 days *until first download*; after download the sale is final (quality issues still made right regardless). Added `downloaded_at`/`download_count` to `purchases` as the enforcement mechanism and as delivery evidence for chargeback disputes.
- `91ce945` **build: stop discarding the Netlify cache, and skip no-op builds** — build command was `rm -rf .next && npm run build`, deleting the cache Netlify had just restored on every single deploy (94 PDFs + 1,369 pages rebuilt cold, every time). Also added a `git diff --quiet` guard against `CACHED_COMMIT_REF` so pushes that can't affect the site skip the build entirely.

**Net effect:** production picked up a real entitlement/refund system and a mobile-breaking layout bug fix in the same sprint that shipped the metro/suburb redesign — worth Kevin spot-checking `RESEND_API_KEY` is actually set (the resume-link email silently no-ops without it) and that Stripe's `charge.refunded` webhook event is actually subscribed to (the code assumes it fires).
